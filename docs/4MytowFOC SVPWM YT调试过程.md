# 4MytowFOC SVPWM YT 调试过程

> 项目：ESP32-S3 双轴云台 FOC 驱动器（yaw + pitch，带激光笔）  
> 阶段：打印件到货、装配成实体云台之后的整机联调  
> 日期：2026-11-12（固件 FW-BUILD 2026-11-12-A → F，共 6 个迭代）  
> 一句话结论：**台架上调好的三环，装上机械负载后全部失效。5 个症状里有 4 个的根因不在"参数没调好"，而在"整定对象变了"和"一个人为的输入解析 bug"。**

## 二、逐阶段记录

### 阶段 1：上电乱动（概率性）

**现象**：手按着 M0 底座让它立住，一烧录上电就"乱动"一下，不是每次都有。

**排查到三个独立机制，都在上电那几十毫秒内发生：**

1. **对齐失败但仍然使能**  
   开环把转子拉到固定电角度（3π/2）测零电角偏移。装好云台后转子被自重拖走，  
   对齐算出的偏移是错的，但代码没检查就 `start()` 使能了 —— 用一个错 90° 的电角度去闭环，  
   力矩方向随机，就是"抽一下"。
2. **`pwm_init` 初始占空比写成 0/0/0**  
   `0/0/0` 不是"不出力"，是**三个下桥全开、绕组短接到地 = 短路制动**。  
   `pwm_enable()` 只拉 EN 脚，所以"使能那一瞬间"电机处于刹车态，  
   带惯量的云台被猛刹 → 抽动。  
   → 改成 `50/50/50`，三相对中性点电压相同，既不出力也不刹车，平滑接管。
3. **对齐重试 4 次，每次都猛吸**  
   重试本身是对的（转子可能没停稳），但每次都施加固定电流硬拉，  
   装了大惯量悬臂之后每次都是"咣"一下。

**改动**：

- 对齐失败 → 三相 `0.5/0.5/0.5` coast，并打 `_align_failed` 标记，  
  `update()` 直接 return，这台彻底不参与控制（宁可不动，也不带着错电角度乱动）
- `ALIGN_RETRY` 4 → **3**
- 新增离散度校验：重试期间转子位置极差 `spread > 0.10 rad`（**5.7°**）就**拒绝标定**，  
  直接 coast 并提示"转子被外力拖走了"

**这里的判断逻辑值得说**：对齐失败时"继续用旧参数使能"比"不动"危险得多。  
嵌入式里**默认动作应该是安全侧**，不是"尽力维持运行"。

### 阶段 2：M1 到点后极小幅度震动

**现象**：`1p1.57` 到点后，在目标位置附近高频小幅震动，声音明显。

**根因**：位置环 P=1.0，输入单位是**度**。误差 1° 时输出 `1 × 1 = 1`，  
但这个 1 的单位是 **rad/s**。也就是说等效增益 = `1 (rad/s per deg) × 57.3 (deg/rad)` = **57 rad/rad**。

这么高的增益把 AS5600 的量化噪声（0.088°/LSB）直接放大成可见的位置抖动。

**改动**：

- `POS_KP_DEFAULT` 1.0 → **0.2**（等效 11.5 rad/rad）
- 新增 `POS_DEADBAND_DEG = 0.2°`：误差小于死区不再修正，直接给 0

**教训**：**混用单位是 PID 调参里最隐蔽的坑**。P=1 看着"很温和"，  
但在"度入、rad/s 出"的链路上等效 57 倍。这也是后面 `p` 命令改成度的伏笔。

### 阶段 3：M0 持续摆动（最长的一段，含两次完整误判）

这是整轮调试的主体，走了 6 步、错了 2 次。

#### 3.1 第一次误判：以为是位置环 P 太高

现象：P=0.2 时 M0 在 ±11° 摆，速度 ±14 rad/s，电流指令撞 ±0.5A 反复反号。  
判断："P 太高 → 过冲 → 振荡"，于是 `0k0.05` 降 P。

结果：**感觉变软了，然后开始慢慢顺时针转。**

#### 3.2 第二次误判：以为是力矩不足

P 越小越"软"、越被拖着转 → 判断"力矩封顶了"。  
因为速度环输出限幅 `VEL_LIMIT_NEAR = 0.5A`，P 再大电流也只能到 0.5A，力矩有上限。

于是加了 `j` 命令在线改力矩上限，让用户发 `0j1.2` / `0j1.8` 验证。

结果：**M0 报 STALL 堵转（0x02）。**

#### 3.3 真相之一：命令被拆断了（这一步让 3.1 和 3.2 全部作废）

查 `?` 输出发现：

```
mode=VELOCITY  target=1.8000
```

调力矩上限的命令，怎么会把模式切成速度模式？

翻 `foc_serial.cpp` 找到 `isSingleLetterCmd()` —— 这张"收到就立即执行、不必等换行"的表里  
放了 `k` `j` `l` `z` `y`，而这些**都是能带参数的**命令。

串口助手逐字符发送时字符间隔可能超过 200ms 的超时阈值，于是：

| 用户发的     | 实际执行                        | 效果                                |
| -------- | --------------------------- | --------------------------------- |
| `0k0.05` | `0k`（查看）+ 速度 **0.05 rad/s** | "变软"（位置环根本没跑）+ 2.9°/s 慢转          |
| `0k0.3`  | 速度 0.3 rad/s                | 17°/s                             |
| `0k0.5`  | 速度 0.5 rad/s                | 29°/s                             |
| `0j1.8`  | 速度 1.8 rad/s                | 遥测第 2 列 = 1.8000（铁证），并被负载卡成 STALL |

**所以前两轮的"变软""慢慢顺时针转""力矩不足"全部是基于假象的结论。**  
所谓"漂移"就是速度模式下 0.05~0.5 rad/s 的匀速转动，跟力矩一点关系都没有。

**修复（FW-BUILD 2026-11-12-A）**：

1. 即时命令表只留**永不带参数**的命令：`r c x s a m e d h ?`  
   `k j l z y g q p v i` 全部移出，必须等 `\n` 或超时
2. 超时 200ms → **800ms**
3. **删除"纯数字 = 速度"兜底**：残片只打印 `stray number -> IGNORED`
4. 未知命令显式拒绝并回显

**这是整轮里最值钱的一条教训**：

> **"把不认识的输入当有效指令"是最危险的一类嵌入式 bug。**  
> 它把用户的调试动作变成了机器的运动命令，而且没有任何报错，  
> 导致连续多轮误判成"力矩不足""PID 参数不对"。  
> 两条铁律：① 命令结束判定以显式分隔符为主，超时只能是兜底且要给足余量；  
> ② 未知/残缺命令必须显式拒绝并回显，绝不"猜一个最像的"。

#### 3.4 决定性现象：手扶能停、轻拨就摆

修完命令 bug 后重新观察，用户给了一句决定性的话：

> "摆的时候我用手轻轻扶稳它，它就会停止摆动，稳住。然后它稳住的时候我用手轻轻一拨，它就会开始摆动。"

**这一句直接定性**：这是**无阻尼（欠阻尼）二阶系统的等幅振荡**，不是力矩不足、不是机械坏、不是 P 调错。

推理链：

- "手扶能停" = 人手提供了**阻尼**（把能量耗散掉）
- "松手就摆" = 系统自身阻尼比 ≈ 0，任何扰动都被完整保留
- 纯 P 位置环就是一根**弹簧**，没有任何东西消耗能量
- P 越小 → 弹簧越软 → 摆幅越小（与实测一致），但**永远不会收敛**

为什么只有 M0 摆、M1 稳？因为 **M0 是竖直 yaw 轴，重心落在轴线上，重力不产生绕 yaw 轴的力矩**  
→ 它就是一个"纯惯量 + 近乎无摩擦轴承"的扭摆，最考验阻尼。  
而 M1 是 pitch 轴，重力矩逼着速度环积分器停在一个恒定工作点"顶着"，反而稳。

#### 3.5 第一次尝试：给位置环加 Kd 速度阻尼

```
vel_cmd = Kp·误差(度) − Kd·实测速度(rad/s)
```

用**实测速度**而不是误差微分（12bit 编码器差分噪声大，D 项会放大噪声）。  
这就是"电子版的手扶"。默认 Kd=0.3，范围 0~3。

**结果：无效。** 用户实测 `0k0.1,0.3` / `0k0.1,0.6` / `0k0.2,0.6` / `0k0.1,1.0`  
四组 —— "跟没发一样，还是摆，幅度也没减小"。

#### 3.6 算账：为什么 Kd 从 0.3 加到 1.0 完全没反应

把 Kd 代进速度环：

```
iq = Pv·Kp·err − Pv·(1+Kd)·ω + Iv·∫(...)
                └── 阻尼系数就是这个 ──┘
```

**Kd 只能把阻尼系数从 Pv 抬到 Pv·(1+Kd)**，而 Pv 原来只有 **0.02**：

| Kd  | 等效阻尼系数 | 绝对增量       |
| --- | ------ | ---------- |
| 0   | 0.020  | —          |
| 0.3 | 0.026  | +0.006     |
| 1.0 | 0.040  | **+0.020** |

阻尼比 ζ = `Kt·Pv·(1+Kd) / (2·J·ωn)`，分子只动了 0.02 的绝对值，ζ 几乎不变。  
**所以"完全没区别"是数学上的必然，不是命令没发进去。**

→ 真正决定阻尼比的是**速度环 P 本身**（1:1 地抬 ζ）。

验算工具：`tools/sim_damping.py`（复刻固件三环：0.2° 死区、0.088° 量化、  
Tf 低通、Tustin 积分、Kt=0.1、dt=3.7ms，纯 numpy 无外部依赖）。

| J=1e-3 kg·m²          | 0.5s     | 1.5s      | 2.5s      | 3.5s      | 结论           |
| --------------------- | -------- | --------- | --------- | --------- | ------------ |
| 旧 Pv=0.02, kd=0.3     | 7.1°     | 26.5°     | 28.3°     | 28.3°     | **发散后持续摆**   |
| 旧 Pv=0.02, kd=1.0     | 6.0°     | 5.4°      | 9.4°      | 14.6°     | 摆小一点，**还在摆** |
| **新 Pv=0.15, kd=0.3** | **6.0°** | **0.18°** | **0.18°** | **0.18°** | **0.52s 收敛** |

仿真还复现了用户主观感受"轻轻一拨就开始摆" —— 旧参数下 System 本身不稳定，  
初始 6° 的扰动会**越摆越大**到 28°，这只有仿真能提前看出来。

**修复（FW-BUILD 2026-11-12-C）**：速度环 P 0.02 → **0.15**

- 新增 `VEL_KP_BASE`、成员 `_vel_kp`、在线命令 `w`
- Kd 保留但降级为"死区里的电子刹车"，不再是主力
- `?` 输出增加 `vkp=`

**实测结果：不摆了。** 这句"不摆了"验证了整个推理链。

#### 3.7 副作用：声音变大 + M1 细震

**现象**：M0 不摆了，但整体声音变大，M1 位置环到点后极小幅度快速震动、声音偏大。

**原因**：PWM 载频 30kHz（人耳听不见），听到的是**电流纹波激励出的结构振动**。  
测速靠"每拍角度差 ÷ 3.7ms"，AS5600 量化 0.088°/LSB → 速度读数天然带约 0.4 rad/s 噪声。  
速度环 P 乘了 7.5 倍，这点噪声就变成电流纹波。

**而 M1 是另一个问题：P 给过头了。**  
阻尼比 ζ = `Kt·P / (2·J·ωn)`，M1（只有笔管）惯量约 `J=2e-5`，比 M0（带整条悬臂）小约 50 倍：

| M1     | 收敛时间  | 结论                |
| ------ | ----- | ----------------- |
| P=0.05 | 0.48s | **安静、收敛**         |
| P=0.10 | 3.63s | 拖很久               |
| P=0.15 | 停不住   | **被噪声推进极限环 = 细震** |

**修复（FW-BUILD 2026-11-12-D）**：

- 速度反馈滤波 `VEL_FILT_TF`：0.01 → **0.025 s**（电流纹波压到约 1/4，  
  而 M0 停住时间反而从 0.46s 变 0.42s —— 阻尼略好，因为滤掉了噪声引起的反向修正）
- 速度环 P **按轴给**：`VEL_KP_YAW=0.15` / `VEL_KP_PITCH=0.05`，配置字段 `MotorConfig::vel_kp`

**这里的通用规律**：

> **同一个参数不能跨轴通用。** P 是"阻尼比旋钮"，但 ζ 与 J 成反比，  
> 惯量差 50 倍的两个轴，最优 P 差几倍。大惯量要"硬"才不摆，小惯量要"软"才不吵。

顺带一个自己踩的坑：`tools/sim_damping.py` 里一阶低通系数一开始写反了  
（`alpha = DT/(Tf+DT)` 应为 `Tf/(Tf+DT)`），导致结论完全反转（"Tf 越大越吵"）。  
**改仿真也要先验证方向**，否则会用一个错模型推出一个更错的结论。

### 阶段 4：云台化 —— 让位置命令可复现

装配稳了之后暴露新问题：**`p` 命令每次语义都不一样**。  
用户实测：M0 的 `0p0` 是 0°、`0p3.5` 是 180°；M1 的 `1p0.7` 是 180°、`1p-2.5` 是 0°，完全没法记。

**三个根因：**

1. **零点不固定**  
   `FOC_Encoder::init()` 里 `_angle_offset = 当前机械角`，即**上电在哪就哪是 0°**。  
   换个上电姿势，`p0` 对应的物理位置就变一次。→ 新增 NVS key `pos_zero`  
   存"云台 0° 对应的编码器绝对角"，上电读取；`h` 命令 = 把此刻位置定为 0° 并写 NVS。
2. **最短路径在 0~180° 区间是错的**  
   行程正好半圈，两端点相差 ±π。`wrapPi` 在边界上会因 0.2° 编码器噪声**随机翻方向**  
   → 表现就是"有时从另一边转过去"。→ 位置误差改成**线性差** `target − _nearFull(full)`，  
   方向由符号唯一确定；`_nearFull()` 只在"编码器漏计整圈"时才折算。
3. **单位不直观** → `p` 从弧度改成**度**。

**修复（FW-BUILD 2026-11-12-E）**：

- `foc_config`：`pos_zero` 存/取
- `foc_encoder`：`getAbsAngle()` / `setAngleOffset()`
- `foc_motor`：`POS_LIMIT_LO/HI_DEFAULT = 0 / π`、`calibrateZero()`、`_nearFull()`
- `foc_serial`：`p` 参数 ×D2R、新增 `h`、`?` 全部用度、`l180` = [0,180°]

验证工具 `tools/verify_range.py` 复刻固件逻辑，跑四种情况全部"区间内走直线、无越界无绕路"：

| 场景                 | 结果              |
| ------------------ | --------------- |
| `p180`（从 0°）       | 误差 +180°，正转 ✓   |
| `p0`（从 176°）       | 误差 −176°，反转 ✓   |
| 端点 179°/181° 抖动    | 方向稳定，不翻转 ✓      |
| `full` 漂了整圈（+360°） | 折算后误差 0，不会转整圈 ✓ |

**通用规律**：

> **"最短路径"只适用于行程 > 180° 的场合。**  
> 行程正好 180° 或更小时，wrapPi 在两端点必然歧义，必须用线性差 + 软限位。  
> 这是舵机类应用的通用写法。

### 阶段 5：命令整理

启动帮助原来 9 行平铺（`'c' 's' 'a' 'm' -> 清档/查档/切对齐/测量`），

## 三、最终成功的参数组合

| 参数           | 最终值                | 原值     | 为什么是这个值                      |
| ------------ | ------------------ | ------ | ---------------------------- |
| 速度环 P（yaw）   | **0.15**           | 0.02   | 仿真+实测：ζ 从 0.1 抬到过阻尼，0.52s 收敛 |
| 速度环 P（pitch） | **0.05**           | 0.02   | J 小 50 倍，0.15 会进极限环（细震）      |
| 速度环 I        | 1.0                | 1.0    | 未动                           |
| 速度反馈滤波 Tf    | **0.025 s**        | 0.01   | 噪声×0.24，且收敛不变慢               |
| 位置环 P        | **0.2**（度）         | 1.0    | 等效 11.5 rad/rad，不放大编码器噪声     |
| 位置环 Kd       | **0.3**            | 无      | 死区里的电子刹车，辅助而非主力              |
| 位置死区         | **0.2°**           | 无      | 压到点抖动，肉眼不可见                  |
| 力矩上限         | 0.5 A              | 0.5 A  | 装配后实测够用                      |
| 对齐重试         | **3 次**            | 4      | 少一次猛吸                        |

## 四、为什么最后能调出来（方法论）

1. **"手扶能停、轻拨就摆"这一句比一堆遥测数据值钱。**  
   它是无阻尼系统的教科书特征。拿到这类定性描述，应该先停下来做物理定性，  
   而不是继续调参数。前面两轮误判的共同问题是：**拿数据但没定性**。
2. **Kd 无效时，不该继续加 Kd，而该问"为什么加不上去"。**  
   把公式代入去看"这个参数到底作用在哪个系数上"，10 分钟就能算清。  
   靠试参数可能要试一天还得不到结论。**能算的不要试。**
3. **仿真不是为了设计，是为了"排除"。**  
   这轮仿真的价值不在算出最优参数，而在证明"旧参数本身不稳定，扰动会越摆越大" ——  
   这个结论在实物上做实验很难看清楚（因为扰动不可控），但仿真一跑就明明白白。  
   并且它提前算出了"M1 会因 P 过大进极限环"，否则改完 P 之后又是一轮瞎试。
4. **先修输入通道，再调控制参数。**  
   命令拆分 bug 让前两轮的结论全部作废。**如果输入层不可信，任何调参都是在噪声上做优化。**  
   这也是为什么后来给 `?` 加了 `vkp` / `kd` / 模式回显 —— 要让"我以为发了什么"  
   和"固件实际收到什么"能对上。
5. **单个参数不能跨轴、跨平台通用。**  
   ζ 与 J 成反比、与 Pv 成正比，惯量变 50 倍，最优 P 也差几倍。  
   这和上次"PID 积分与采样率强耦合"是同一条规律的两个侧面。

## 五、如果重来一次，能省掉哪些弯路

| 弯路                          | 本可以怎么省                                              |
| --------------------------- | --------------------------------------------------- |
| 降 P 看到"变软 + 慢漂"就判力矩不足       | 先看 `?` 的 `mode=` 字段。调参命令不该改模式，一出现 `VELOCITY` 就该怀疑解析 |
| 用 `k` 调 Kd 治摆动，试了 4 组共 1 小时 | 先做量纲/公式推导：`iq` 里 ω 的系数是 `Pv(1+Kd)`，Pv=0.02 时 Kd 无意义 |
| 只能在实物上试"稳不稳"                | 先写三环仿真扫 Pv/J，10 分钟得到 ζ 表和收敛时间                       |
| M1 跟着 M0 用同一个 P             | 意识到"惯量差 50 倍"，一开始就按轴给                               |
| `p` 每次语义不同，靠记 `0.7`/`-2.5`  | 早期就把零点存 NVS —— 标定类参数一开始就该持久化                        |

## 六、面试可以怎么讲（三段）

**第一段 · 讲现象定性**

> "装成实体云台后 M0 一直摆。我试过往位置环加 Kd 阻尼，四组参数从 0.3 加到 1.0，  
> 用户反馈完全没区别。我停下来推导了一下：位置环的 Kd 是乘在内环速度误差上的，  
> 代进速度环以后，它只能把阻尼系数从 Pv 抬到 Pv(1+Kd)。而 Pv 当时只有 0.02，  
> 所以 Kd 加到 1.0 也只把系数从 0.02 抬到 0.04 —— **没效果是数学必然，不是命令没发进去**。  
> 真正的旋钮是速度环 P 本身。改到 0.15 之后，实测不摆了。"

**第二段 · 讲一个"反直觉"的坑**

> "这轮最花时间的地方不是调参，是一个输入解析 bug。


> 我有一张'收到就立即执行、不用等换行'的命令表，里面混进了能带参数的调色命令。
> 串口助手逐字符发 `0k0.05` 时，在敲到 `0k` 就被判定完整并执行，
> 剩下的 `0.05` 单独成一条命令，落到兜底分支被当成速度 0.05 rad/s 执行。
> 结果就是'我发了个调参命令，电机自己慢慢转'，而且没有任何报错。
> 我据此连续两轮误判成力矩不足、PID 参数问题。修法是：即时命令表只留不带参数的，
> 超时从 200ms 放宽到 800ms，并且彻底删掉'纯数字猜成速度'的兜底 —— 未知命令必须显式拒绝。
> 这件事让我记住了一条：**把不认识的输入当有效指令，是最危险的一类嵌入式 bug**，
> 因为它把调试动作静默转化成了机器动作。"

**第三段 · 讲"同一参数不能跨轴"**
> "改完速度环 P 之后 M0 好了，但 M1 出现高频细震。原因是两颗轴惯量差了约 50 倍 ——
> 阻尼比 ζ 和惯量成反比，P=0.15 对带整条悬臂的 yaw 轴正好，对只有笔管的 pitch 轴就过头了，
> 把测速噪声放大成了极限环。所以最后速度环 P 是按轴分开给的：yaw 0.15、pitch 0.05，
> 同时把速度反馈滤波从 10ms 加到 25ms 压噪声。
> 这和'PID 参数不能跨平台照抄'是同一条规律的另一个侧面 —— **参数只在特定惯量下有意义**。"
