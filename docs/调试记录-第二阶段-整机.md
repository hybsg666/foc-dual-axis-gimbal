## 二、逐阶段记录

### 2.1 先说我犯的两个错（不可逆的那两个）

**错误一：在电机震着、通信未必稳的时候敲 `1c`（重标电角度）。**
`c` 会重跑对齐：开环把转子吸到固定电角度、读编码器、算偏移、写 NVS。
只要那一瞬间转子被自重拖走或读数抖，算出来的值就是废值。
实测把 M1 的 `zero_electric_angle` 从 **1.0082** 写成了 **2.4820**（差 84°）。
后果的症状特别有欺骗性：**电机通着电却软得像断电、手能掰动、线圈发热、有齿槽声**，
而且启动日志全绿、对齐"自洽"——因为它就是按那个错值算出来的。

> 这一条 2026-10-16 已经写进过教训："严禁在转动 / 通信不稳时敲 `c`"。这次是重犯。

**错误二：顺手敲 `1h`（重定机械零点）。** 直接把 `pos_zero` 覆盖掉，`1p0` 就回不到原来的 0°。

**补救方法（值得记住）**：两处都没有备份，最后是**翻历史 transcript 的 jsonl** 找回原始数值
（`zero_electric_angle = 1.0082`、`pos_zero = 5.7540 rad`），再写回 NVS。
**教训：任何写 NVS 的命令，执行前先把当前值 `?` 出来记一笔。**

### 2.2 全量回滚：只能靠源码快照，不能靠记忆

用户要求"直接返回标定完成那天的版本，代码一模一样，后面加的功能都不要"。
我先做了一件对的事：**不去凭记忆手改，而是找源码快照整份覆盖**。

快照在 `~/.workbuddy/file-history/<sessionId>/<hash>@vN`（纯文本），把 11-12 那天的 7 个文件
（`foc_motor.cpp/.h`、`foc_control.cpp/.h`、`foc_encoder.cpp/.h`、`foc_serial.cpp`）整份还原，
还原前把当前版本备份到 `4YT/.workbuddy/backup-2026-11-18-B/`。

> 为什么强调"整份覆盖"：参数能记住，但**逻辑改动的累积**记不住。
> 我这两周往 `foc_motor.cpp` 里加了成形器、跳变保护、12ms 测速窗、符号层……
> 任何"我以为只是个小改动"的地方都可能是震动的来源。回滚是唯一能把未知项清零的手段。

### 2.3 "以前不震、后来一直震"的根因（这是本阶段最有价值的一条）

回滚后对比 11-12 版与后来的版本，差别就在上电这几行：

```cpp
// 11-12 版：上电时若当前角在限位外，把限位临时扩到当前角（只改内存，不写 NVS）
if (boot_full < _pos_lo) _pos_lo = boot_full;
if (boot_full > _pos_hi) _pos_hi = boot_full;
_target_pos = boot_full;          // 于是上电就锁在当前位置，永不顶边界
```

```cpp
// 11-16 之后被"改进"成：
_target_pos = constrain(boot_near, _pos_lo, _pos_hi);   // 夹回边界
```

差别在天上地下：M1 上电读数 329.7°（等价 −30.3°），限位是 [0, 180]。
旧版把它锁在 −30.3° 原地不动；新版把目标夹到 0°，误差恒为 30°，
**位置环就一直在往边界顶，iq 顶到 0.5A 限幅，顶不动弹回来再顶** ——
就是用户说的"一上电就自己原地震"。而且这时候任何位置命令都在同一场震里，
所以"发了位置环命令更震"。

**但是** 11-12 版的"扩限位"本身是个定时炸弹（11-16 已经吃过一次：读数偏整圈时
限位被扩成 `[-267.5, 180]`，软限位从此永久作废）。所以最终没有照抄，而是第三种做法：

```cpp
// 11-18-D：限位永远保持 NVS 标定值；姿态锁定用"归一化到等价角"
_target_pos = _nearFull(boot_full);   // 折回同一物理位置的等价角，不动限位
```

- 在限位内：`_nearFull` 返回原值，行为不变；
- 读数偏整圈：折回等价角（同一物理位置），坐标口径自动对齐；
- 真在限位外：锁在界外原地（err=0 不冲），下一次 `p` 命令时 `_clampTarget` 自然领回区间。

> **方法论**：保护阈值（软限位）**只能人来改，代码永远不许自动放宽**；
> 要治"读数越界"，治的是**读数口径**，不是保护阈值。

### 2.4 回滚是起点，不是终点：两个功能要加回

回滚版把后来加的功能一起带走了，其中两个是刚需，用**最小改动**加回：

**① `user_sign`（M1 方向）**
现象：`1p0` 停在 0°，`1p90` 却跑到 90° 的对面。
根因：M1 编码器是反装的，内部累积角增大 = 物理顺时针；用户坐标系要求"增大 = 逆时针"。
所以他在 11-12 版里一直靠发负角度凑（`1p-30` = 物理 0、`1p-120` = 物理 90）。

做法：`MotorConfig::user_sign`（M0 = +1，M1 = −1），**只作用于对外接口**：
`setTargetPos` / `setTargetVel` / `push(pos)` 的入参、`l` 限位的镜像、所有显示（`?`、波形、回显）。
三环内部、编码器、换相 `dir`、`zero_electric_angle` **一律不动**。

> **为什么不能翻 `cfg.dir` 或编码器 `_dir`**：11-16 试过三次，全部失败，而且失败方式各不相同：
> · 只翻读数 → 速度环正反馈 → 360° 快速乱摆
> · 只翻换相 → 位置环反方向 → 发位置不动（0.5A 全变铜损，发热）
> · 两个一起翻 → 通着电却软得像断电、手能掰动
> 在对外坐标翻符号，内部数学完全不变，**不可能引起正反馈**——这是唯一安全的层次。

**② `q` 命令的段间停顿 `dwell`（毫秒）**
需求：模拟激光笔跟踪 —— 跳到目标 → 停 2 秒 → 再跳下一个。原来的 `q` 是段间不减速连续跑。
做法：`MotionCmd::dwell` + `_dwell_until`；轨迹跑完置 `millis() + dwell`，
停顿期间位置环继续锁 `_target_pos`（上一段终点），不出队下一条；
`(int32_t)(millis() - until) < 0` 判回绕。`dwell = 0` 时与旧行为完全一致。

```
q0,100,4.5,2000;1,40,4,2000;0,52,4.5,2000;1,132,4,2000
   └电机 └角度 └rad/s └停顿ms
```

### 2.5 用户授权我上机自测，第一件事是**修测量**而不是调参

第一次测 M0 静止，结果"位置峰峰 50°、速度峰峰 21 rad/s"。这个数不可能，因为电机肉眼只是微动。

查下去发现：**遥测打印每 loop 一行**（`m` 一开就从"每 100 loop"变成"每 loop"），
一行 60 字节 @115200 ≈ 5.2ms，**把控制环从 ~1kHz 压到 130Hz**。
测出来的"抖动"是打印自己造成的。

改成按 `millis()` 定时（`measure` 时 50Hz、平时 10Hz）后，同一台电机测出来是 **0.88°**。
顺手加了常驻的 `[STAT] ctrl loop = xxx Hz`，以后一眼能看出 loop 有没有被拖慢。

> **教训：先证明测量不干扰被测对象，再谈数据。**
> 这一条在 TS 里也会出现（打日志打出 20 倍延迟），道理一样。

### 2.6 电流采样噪声：力矩纹波的主因

怎么把"控制环的问题"和"测量的噪声"分开？用了一个很干净的手法：

**电流模式给 `0i0`（iq 指令 = 0），只看 iq 读数。** 此时控制环不参与，读数抖多少就是纯测量噪声。

| 条件 | iq 读数峰峰 |
|---|---|
| 单次 `analogRead` | **0.54 A** |
| 位置模式静止时 | 0.49 A（几乎同一个数 ⇒ 静止的 iq 抖动**全是 ADC 噪声**） |
| ADC 2 次平均 | 0.23 A |
| ADC 4 次平均 | 0.21 A（控制频率降到 420Hz） |
| ADC 8 次平均 | 0.088 A（控制频率 300~400Hz，**M1 直接开始大幅摆动**） |

选 **2 次**：噪声降 40%，控制频率仍有 965Hz。
8 次那档是活教材——**采样率一降，同一套 PID 的等效积分量就变了**，
上一阶段"采样率与 PID 强耦合"的老坑立刻重现。

### 2.7 测试中撞出来的两个致命坐标 bug

**bug A：`_nearFull()` 被"越限放宽"骗了。**

我自己在测 `0p0` 时把局面演进这个 bug（之前一直潜伏）：
M0 上电累积角 −280°（物理其实在 79.6°），`0p0` 本该走 −79.5°，
实际规划了 **+281°**，一路走到机械限位顶死，`iq` 打满 **5A**（限幅才 0.5A），两轴 SAT。

链条：上电时"越限就放宽限位"把 `_pos_lo` 拉到了 −280°，
而 `_nearFull` 的判据正是"离限位端点是否半圈内" —— 它认为就在弧上、**不折算**，
于是位置环拿着 −280° 当坐标去算误差。

修法：限位不动 + 姿态锁定与**所有轨迹起点**（`queueStart`、队列 non-norm 分支）都用 `_nearFull()`。
修复后实测：

| 命令 | 轨迹行程 | 落点 |
|---|---|---|
| `0p0` | −79.5°（原来 +281°） | 物理 359.8° ≈ 0° |
| `0p90` | +90.2° | 90.1° |
| `0p45` | −45° | 44.8° |

**bug B：`g` 指向命令坐标系错配。**
`foc_control_get_full()` 返回的既不是用户坐标、也没归一化；
而 `foc_get_pos_limit_lo/hi()` 是用户坐标（含 `sign`）。
M1 的 `user_sign = −1` 后，内部角是负的，和 0~180° 的用户限位根本不是一套坐标 → 长期误钳。
新增 `FOC_Motor::fullAngleNear()` / `foc_control_get_full_near()`（归一化 + 乘 sign），
逆解改用它。实测 `g0,1,0.5` 两轴 SYNC 同时到位。

### 2.8 串口坑（值得单独记，浪费了一小时）

| pyserial 打开方式 | 结果 |
|---|---|
| `dtr=False` | **命令一个都进不去**，但遥测照常接收 —— 看起来"完全正常" |
| `rts=True` | 板子被复位 / 卡在下载模式，之后连遥测都没有，只能重新烧录 |

正确：**`dtr=True, rts=False`，且在 `open()` 之前设置**。
（`open()` 之后再改会触发 ESP32 的自动复位电路，每次连串口重开一次机，4.4 秒启动期的命令全丢。）

之前所有"发了命令没反应"的怀疑，有一半是这一条，不是固件 bug。

### 2.9 验收

**静态指标（FW-BUILD 2026-11-18-D）**

| | 位置峰峰 | 位置 std | iq 峰峰 |
|---|---|---|---|
| M0 | **0.35°**（改前 0.53°） | 0.08° | 0.023 A |
| M1 | 0.70° | 0.16° | 0.029 A |

`0.35° ≈ 12bit AS5600 的 4 个 LSB`，已经是这套硬件的量化底噪，再压只能加死位（代价是定位精度）。
参数一个没改：`kp 0.2 / kd 0.3 / 速度环 P 0.15(yaw)、0.05(pitch)` —— 我试过 `kp 0.13`，抖动反而涨到 0.88°。

**动态指标（跟踪工况，用户确认"效果很好"）**

双轴在 30~150° 内无规则跳动，每点停 2 秒，到位速度 M0 4.5 rad/s（≈258°/s）、M1 4.0 rad/s：

- 停住的 2 秒里没有可见回蹭
- 跳到新目标无过冲回收
- M1 快速段无跟不上（`iq` 未贴限幅）
- 三条 12 段序列（约 30 秒/条）连跑，无 `[FAULT]`、无 `SAT`

## 五、为什么最后能通（方法论）

1. **先分清"是我改坏的"还是"本来就有"。**
   用户一句"以前一直不震"，直接把排查方向从"调参"改成"找回归点"。
   回滚到能工作的基线，是最高效的二分法 —— 而且它是**唯一能把未知项清零**的手段。
2. **回滚要用源码快照，不要用记忆。** 记忆里"我只是加了个小判断"，
   实际上可能是三个文件互相耦合的改动。
3. **一次只改一个变量。** 这一阶段前半段之所以乱，是因为一晚上推了 8 版、
   每次改一堆，炸了之后无法归因。后半段改成"改一处 → 真机验证 → 再动下一处"，节奏立刻顺了。
4. **先修测量，再调参数。** 打印占空 7.6%、单次 ADC、`dtr` 没给 —— 这三件都不是控制问题，
   却制造了全部"控制问题"的假象。
5. **隔离法分离噪声源。** `0i0` 一个命令就把"控制环抖动"和"电流采样噪声"分开了。
   值钱的是这个动作，不是结论。
6. **保护阈值只能人来改。** "越界时自动放宽"看起来友好，实际上是永久性失效的入口，
   这一条在这两周内咬了两次。
7. **改的是口径，不是被测量的对象。** 方向反了就去翻符号（对外坐标），
   不要去翻编码器或换相 —— 后者会同时破坏位置环负反馈和换相对齐。

## 六、面试可以怎么讲（三段）

**段一（问题定位）**
"整机装好之后电机一上电就原地高频震。我一开始以为是 PID，试了两天参数反而更乱。
后来发现根因在上电时的一段逻辑：当时的姿态角在软限位之外，固件把目标位置夹到了限位边界，
位置误差恒有 30°，位置环就一直往边界顶，电流顶到限幅、顶不动弹回来再顶。
改成'限位永远不动、姿态锁定用归一化角'之后，上电就是静止的。"

**段二（回滚与工程纪律）**
"中间我犯过一个错：连续改参数、一次改好几处，结果炸了没法归因。
最后我从源码快照把两周前能工作的版本整份还原，先拿到一个已知可用的基线，
再一个一个往回加功能。这件事让我改了两个习惯：一次只改一个变量，
以及任何写 NVS 的命令执行前先把当前值读出来记一笔。"

**段三（测量学）**
"调抖动的时候，测出来位置峰峰 50°，但电机肉眼只是微动。
查下来是遥测打印每一拍都打，一行 5 毫秒，把控制环从 1kHz 压到 130Hz —— 测的是打印造成的抖动。
改成定时打印后真实值是 0.5°。最后定位到电流采样只有单次 ADC，零电流时读数还在 ±0.27A 跳，
这个噪声被电流环调成了力矩纹波；改成两次平均后纹波降到 0.23A，静止抖动降到 0.35°，
这已经是 12bit 编码器的 4 个最小刻度，是硬件底噪。"

## 七、下一步：CANopen（CiA 402）

当前是自定义 CAN 帧（MCP2515 @ SPI，21/39/38/40 + INT 41），能跑但不利于组网。
下一阶段按 CiA 402 从站做，双电机两个节点 ID：

| 优先级 | 内容 |
|---|---|
| P0 | 对象字典骨架（0x1000/0x1001/0x1018 身份，0x6040/0x6041 控制字与状态字，0x6060/0x6061 模式，0x607A 目标位置，0x6064 实际位置，0x606C 实际速度） |
| P0 | 状态机：Not Ready → Switch On Disabled → Ready → Switched On → **Operation Enabled** → Quick Stop / Fault |
| P1 | SDO 服务器（0x600/0x580，分段传输，能读写任意索引） |
| P1 | PDO：RPDO1 = 0x6040 + 0x607A，TPDO1 = 0x6041 + 0x6064 + 0x606C；事件定时 + SYNC 同步 |
| P1 | NMT（0x000 start/stop/reset）+ 心跳（0x700+ID）+ EMCY（0x080+ID，把现有 `fault` 位映射过去） |
| P2 | SPI 时钟 1MHz → 4MHz（当前 CAN 帧率被 SPI 限死），以及总线错误计数/恢复 |

验收口径：能用 Canopen 主站（或 Python canopen 库）完成
"上电 → NMT start → 切到 Operation Enabled → 用 PDO 下发目标位置 → 读回实际位置"的完整闭环。
