# 定点跳跃测试预设（FW-BUILD 2026-11-17-I）

> 当前硬事实：M0 实测可达行程 **0 ~ 116.9°**（比原来少 19°，原因是转子撞到手，定子被扭动）。
> 所以下面所有预设的**上限都压在 105°**，留 12° 余量。
> 定子锁死并重新标零后，行程可能回到 ~135°，那时再把上限提到 130。

## 0. 每次测试前跑这三条

```
0r
1r
?
```

`?` 要看到两行 `fault=0x00`，且 `limit=[0.0,180.0]deg`。
**建议把软限位收紧到实际行程**（防撞挡块，会写进 NVS）：

```
0l105
1l105
```

> 松掉软限位 = 每次撞挡都是 0.5A 顶死 3 秒 → 过流故障，我们已经被咬过一次。

---

## 1. 基础两点指向（验收主力，先跑它）

```
0b45@600,105@600;450
1b30@600,90@600;450
```

看点：落地后有没有回弹；每个位置停稳后是否还在轻微抖动。
这是最接近"激光在两个目标间来回指"的工况。

## 2. 三点巡航（行程覆盖更全）

```
0b30@500,65@500,100@500;450
```

三个点间距 35°，能同时看到"短跳"和"长跳"的差别。

## 3. 四点错落（短跳/长跳/中跳混编）

```
0b25@500,105@500,60@500,90@500;450
```

跳距依次 80° / 45° / 30°，用来暴露"某些角度特别震"的问题。

## 4. 快节奏（每跳 320ms，最"啪"）

```
0b45@400,95@400;320
```

看点：这是速度上限的试探。如果出现明显过冲/回弹，把 320 改成 380。

## 5. 慢节奏大行程（稳定性基准）

```
0b20@800,100@800;700
```

慢速下如果还抖，那就不是速度引起的，是控制或机械。可作为"基准对照组"。

## 6. 微幅小步（只走 20°，专测末端）

```
0b60@400,80@400;400
```

行程小、速度低，最容易看出"到位后 ±0.5° 的微振"，也就是你之前说的"轻微震"。

## 7. 双轴联动（激光扫方格 / 斜线）

两轴同一条命令、同一节奏，两条线一起发：

```
0b40@500,90@500;450
1b50@500,85@500;450
```

看点：两轴会不会**不同时到位**（错开几十毫秒）。
⚠️ 已知问题：当前固件每轴各自从"收到命令那一刻"起算相位，
所以两条命令相隔多久、就错开多久（见下节第 3 条）。

## 8. 单轴基础动作（确认底层没坏）

```
0p90          # 位置模式，走到 90°
0v0.5         # 速度模式，0.5 rad/s ≈ 28.6°/s
0i0           # 电流开环 0（coast，可手掰）
0boff         # 停掉跳跃，锁在当前角度
```

## 9. 跟踪工况（激光笔跟随，2026-11-18-D 实测通过）

双轴在 30~150° 内无规则跳动，**每点到位停 2 秒**，到位速度 M0 4.5 rad/s / M1 4.0 rad/s。
`q` 的第 4 个字段 = 停顿毫秒。

> M0 实际行程只有 45~105°，所以下面 M0 的点都压在 45~105；
> M1 走满 30~150。把 M0 写到 150 只会被软限位夹到 105，白测。

**序列 1**
```
q0,100,4.5,2000;1,40,4,2000;0,52,4.5,2000;1,132,4,2000;0,96,4.5,2000;1,64,4,2000;0,45,4.5,2000;1,148,4,2000;0,88,4.5,2000;1,35,4,2000;0,105,4.5,2000;1,118,4,2000
```

**序列 2**
```
q0,62,4.5,2000;1,145,4,2000;0,104,4.5,2000;1,32,4,2000;0,48,4.5,2000;1,98,4,2000;0,95,4.5,2000;1,52,4,2000;0,58,4.5,2000;1,140,4,2000;0,102,4.5,2000;1,75,4,2000
```

**序列 3（跳得更狠）**
```
q0,45,4.5,2000;1,150,4,2000;0,105,4.5,2000;1,30,4,2000;0,72,4.5,2000;1,120,4,2000;0,45,4.5,2000;1,66,4,2000;0,105,4.5,2000;1,150,4,2000;0,80,4.5,2000;1,38,4,2000
```

每条约 30 秒，打完 `[QUEUE] ... done` 再发下一条（跑一半发新命令会清队列）。

看点：①停住的 2 秒里有没有回蹭 ②跳到新目标第一下有没有过冲 ③快速段 `iq` 有没有贴 `jl`
（贴了就先 `1j1.2` 放力矩上限再重跑）。

## 怎么判断"没问题了"

| 项目 | 合格线 |
|---|---|
| 每个落点稳态峰峰 | ≤ 1.0° |
| 落地过冲 | ≤ 2°，且 1 秒内收住 |
| 到位误差 | ≤ ±0.5° |
| 速度峰值一致性 | 同一条命令连跑 3 次，峰值差 ≤ 5% |
| 全程无 `[FAULT]` / 无 `SAT` | 必须 |

连跑 3 轮都满足，就可以收工去搞 CANopen 了。

## 出问题先看哪

- 完全不动 → 发 `?`，看 `fault=` 和 `limit=`；再发一次命令看有没有 `[RX]` 回显（没回显=串口没收到）
- 卡在某个角度、`SAT` → 撞挡块了，目标超出实际行程
- 到位很慢（1 秒还没到） → 减速包络太保守，`0e8000`（默认）或 `0e2000`
- 一直抖不停 → 先 `0boff` 停掉，再看是"停住也抖"（机械/定子）还是"只在下落时抖"（控制）
