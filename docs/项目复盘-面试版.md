## 0. 三句话讲清这个项目（开场背下来）

> 我用 **ESP32-S3 从零写了一套 FOC 驱动器**（没有用 SimpleFOC 这类现成库），驱动两台 **DengFOC 2208 空心轴盘式云台电机**，做成一个**双轴指向云台**，最终带激光笔做空间指向。
>
> 三环串级（电流 / 速度 / 位置）全写在双精度不够、只能单精度的 MCU 上，控制频率对齐到 DengFOC 的几千 Hz 级别。
>
> 机械部分没有现成件，我根据电机实物尺寸**自己用 Python + CSG 布尔运算生成 STL**，走 3D 打印；通信从串口做到 CAN，下一步上 CANopen。

一句话版本：**"从 PWM 到机械件全栈自己做的一个双轴伺服系统。"**

## 3. 六个"翻车 → 定位 → 修复"故事（面试核心素材）

### 故事 1｜静止微震：8 轮补丁全失败，根因是采样率 ⭐最值得讲

**现象**：电机停住后原地微微震动，偶尔突然抖一下。M0 严重、M1 较轻。

**我最初怎么想（全错）**：
以为是死区、积分饱和、编码器噪声。于是依次加了 8 个"补丁"：
死区补偿 → 死区内 iq 清零 → 软死区 → 到位锁定 → 冻结积分 → 慢自适应 → uq 低通 → 位置误差低通 → 每个电机单独的 6° 死区。
**全部失败，有的还更糟。**

**怎么定位**：
用户提供关键线索——"同一颗电机用 DengFOC 原版位置环很稳，不震"。
→ 说明不是硬件。于是逐项对比两个工程的**运行条件**，而不是参数：
- DengFOC：`loop()` 全速跑，几千 Hz
- 我的：`loop()` 里有 `delay(1)` → 约 **270 Hz**

**根因**：
PID 的积分项是"每步累加"。Tustin 离散化下，积分增量 ∝ `I × Ts × 误差`。
采样周期 `Ts` 从 0.2 ms 变成 3.7 ms（**差 18 倍**），同样的 `I=1.0` / `I=200` 每步积分量就放大 18 倍
→ 积分过冲 → 输出抖动 → 电流抖动 → 震动。
**参数本身没错，是它跟采样率强耦合。**

**修法**（三处，都是"提高采样率"）：
1. 删掉 `loop()` 里的 `delay(1)` → 控制频率提到数千 Hz
2. I2C 从 100 kHz 提到 **400 kHz**（编码器读取是主要耗时）
3. 串口遥测从每 5 次 loop 一次改为每 100 次 loop 一次（打印是阻塞的）

**结果**：所有补丁删掉，回归**纯三环**，参数直接用 DengFOC 那套，**停住一动不动**。

**这段能体现什么**：
- 不迷信"加补偿"，先确认两个系统的**运行条件是否等价**
- 理解 PID 参数与采样率的耦合关系（离散化）
- 敢于**删代码**——8 个补丁全部删除

### 故事 2｜编码器"丢弃一帧"变成永久冻结 ⭐最有技术含量

**现象**：发位置指令，电机转到一半突然停住不动，3 秒后报故障码 4（位置超差）。偶发，两台都出现。

**代码里的原始写法**：
```c
float inst_speed = fabsf(d_angle) / Ts;
if (inst_speed > 50.0f) {   // 认为是毛刺
    _angle_prev_ts = now;   // 只更新时间戳
    return;                 // 没有更新参考角度 _angle_prev
}
```

**看起来**：丢弃一帧坏数据，下一帧就好了。
**实际上**：**永久冻结**。

推理链：
- 第 N 拍：读数跳变，`d_angle` 很大 → 丢弃，但 `_angle_prev` 还是旧值
- 第 N+1 拍：`d_angle` 仍是"旧参考 → 新读数"那个大值，而 `Ts` 已经回落到正常小值
- → `inst_speed` **反而更大** → 继续丢弃
- → 参考点永远追不上读数，**角度永久冻死**

后果：位置环看到"没到位、也没在动" → 一直加力 → 电机被顶到限位 → 报位置超差。

**修法**：
- 连续 2 拍超限 → 仍当毛刺丢弃
- **连续 3 拍仍超限 → 判定参考点失配，强制 `_angle_prev = val` 重同步**，并打印 `[ENC] resync`
- 原则：**宁可角度跳一下，也绝不允许冻死**

**这段能体现什么**：
- 能看出"防御性代码"里隐藏的状态机死锁
- 异常恢复要能**跳出异常状态**，不能只做"跳过本次"

### 故事 3｜CAN 参数不能照抄：量纲 + 有没有电流环

**背景**：为了对齐 DengFOC 表现，照抄它的速度环参数 `SET_VEL_PID(0.02, 1, 0, 100000, 0.5)`。

**踩坑**：照抄后反而**疯狂震动**。

**根因（两层）**：
1. **量纲不同**：DengFOC 的 `0.5` 是**电压 0.5 V**——它的 `setVelocity` 直接调 `setTorque()`，中间**没有电流环**（那句 `SET_CURRENT_PID` 是死代码，从没被调用）。
2. 我的工程速度环后面**串了电流环**，同一位置的 `0.5` 变成 **0.5 A**。12.6 V 母线、相电阻约 10 Ω，0.5 A ≈ 5 V，实际施加的力矩是 DengFOC 的十倍。

**修法**：不要照抄数值，要**对齐物理量**。把速度环输出重新按"电流"标定，并把限幅压到 0.5 A（对应实际需要的力矩）。

**这段能体现什么**：
- 读别人的代码要读**调用链**，不能只看参数表
- 同样的数字在不同控制结构里物理意义完全不同

### 故事 4｜机械逆向：从照片到 STL 的三次纠正

**问题**：买不到配套打印件（云台双层编码器要 50 元，舍不得），只能自己画。
但电机是**空心轴盘式外转子**，不是普通长轴电机，一开始完全看错。

**三次纠正**：
1. 第一次以为是"套 3 mm 长轴" → 用户指出顶部是**短凸台**
2. 第二次以为是"2×M2 螺钉" → 实际是 **3×M3 品字形，相邻 10 mm**
3. 第三次以为编码器板是"φ20 小板" → 实际是**整个 φ30 底面 + 4 个铜螺柱（相邻 21 / 对角 30）**

**还踩了一个隐藏 bug**：
早期用"纯加法叠环"造孔（大环套小环），结果**小孔环被下面的大板盖住，螺丝孔根本没打穿**——打印出来拧不进螺丝。
→ 改用 **CSG 布尔运算**（trimesh + manifold3d），实心盘直接减圆柱体，才是真通孔。
→ 并且写了**自动校验**：`is_watertight` + 对每个孔中心逐点 `mesh.contains`（孔内必须 False、实体必须 True）。

**这段能体现什么**：
- 逆向建模要对**实物尺寸负责**，不能靠想象
- 几何正确 ≠ 可制造：必须验证水密性和孔是否贯通
- 用自动化校验代替肉眼检查

### 故事 5｜保护误报：先关掉，再查（工程取舍）

**现象**：位置模式频繁报故障码 4（位置超差），打断测试。

**分析**：故障码 4 的判据是"误差 > 阈值 + 速度≈0 + 持续 3 秒"，它**只是结果，不是原因**。真正要查的是"为什么没走到"。

**取舍**：调试阶段把它**关掉**（编译期开关 `POS_ERROR_PROT_ENABLE 0`），保留真正危险的保护（过流 3.5 A、堵转、指令超时）。
理由是：**调试期误报比不保护更影响效率**，而且有 `[SNAP]` 数据可以替代它做诊断。

**但要说清**：
- 不报警 ≠ 走到了。判定标准是遥测实际位置是否收敛到目标 ±0.02 rad。
- 等装好结构、要长期运行时，必须把开关打开——那时候它是**防止指令把机械顶坏**的最后一道保险。

**这段能体现什么**：
- 能区分"报警"和"故障根因"
- 保护策略要按阶段调整（调试 vs 量产）
- 关掉保护的同时必须给出替代的可观测手段

---

### 故事 6｜可观测性：从"猜"到"测"

**问题**：前面几轮反复"猜原因 → 改参数 → 失败"，效率极低。

**做了什么**：
1. **`[SNAP]` 故障现场快照**：环形缓冲 20 帧 × 100 ms = 最近 2 秒的 `pos / vel / iq / vcmd / err`，一进故障就全部打印。
   - `iq` 恒 0.5 且 `pos` 不动 → 真被挡住
   - `iq` 从 0.5 掉到 0 → 中途失力（电源跌落）
   - `vcmd=30` 但 `iq≈0` → 电流环没输出
2. **`[STUCK]` 即时诊断**：不等 3 秒报故障，400 ms 就打印
3. **遥测可视化面板**：Web Serial 直连串口，把 14 列数字变成仪表盘 + 位置跟踪曲线
4. **`diag_pos.py`**：一键跑完"清故障 → 发目标 → 采数据 → 给结论"

**这段能体现什么**：
- 嵌入式调试最难的是**看不见内部状态**，所以要先建设观测手段
- 有数据再改代码，不要凭感觉调参

### 4.3 CANopen（P2，面试高频）
现在的 CAN 是**自定义帧**，下一步做标准 **CANopen CiA 402 驱动器子协议**：

| 项 | 内容 |
|---|---|
| 物理/数据链路 | CAN 2.0A，500 kbps（已有 MCP2515，可直接复用） |
| 对象字典 OD | CiA 301 基础 + CiA 402 驱动器子协议 |
| **状态机** | `Switch on disabled → Ready to switch on → Switched on → Operation enabled → Fault` |
| 控制字 / 状态字 | `0x6040` 控制字、`0x6041` 状态字（位组合驱动状态迁移） |
| 运行模式 | `0x6060`：1=PP 轮廓位置、3=PV 轮廓速度、6=HM 回零、8=CSP 周期同步位置 |
| 目标 / 实际 | `0x607A` 目标位置、`0x6064` 实际位置、`0x606C` 实际速度、`0x6077` 实际转矩 |
| PDO | `0x180` TPDO（反馈）、`0x200` RPDO（指令），映射可配 |
| SDO | `0x600/0x580`，读写对象字典 |
| NMT / 心跳 | `0x000` 节点管理、`0x1017` 心跳周期、`0x1001` 错误寄存器 |

实施步骤：
1. 先做 SDO（读 0x1000 设备类型、写 0x6060 模式）
2. 再做状态机（0x6040/0x6041 位逻辑）
3. 再做 PDO（周期同步，把三环指令与反馈映射进去）
4. 最后做 NMT + 心跳 + 故障复位

### 4.4 力控（P3，面试高频）
现在的力矩能力只有"电流模式"（`MODE_CURRENT`，iq 闭环）。要做真正的力控需要补三层：

| 层 | 内容 | 现状 |
|---|---|---|
| 力矩标定 | `τ = Kt × iq`，`Kt = 1.5 × PP × ψf`，实测拟合 | ❌ 未做 |
| 重力补偿 | 云台俯仰轴有重力矩 `τ_g = m·g·L·cos(θ)`，前馈掉 | ❌ 未做 |
| 摩擦补偿 | 库仑摩擦（符号函数）+ 粘滞摩擦（正比速度），低速时占主导 | ❌ 未做 |
| 阻抗控制 | `τ = Kp(qd−q) + Kd(q̇d−q̇) + τ_ff`，可调刚度/阻尼 | ❌ 未做 |
| 外力估计 | 无传感器用**扰动观测器**（反电动势 + 动力学模型反推） | ❌ 未做 |

云台本身用不到力控（位置控制就够），但这是把驱动器做成**通用伺服**的关键一步，也是面试最能展开的部分。

### 4.5 指向功能（P4）
1. **角度指向**（基础已有）：给 yaw/pitch → 双电机联动，缺零位偏置
2. **空间点指向**：`(x,y,z)` → 逆解
   ```
   yaw   = −atan2(x, y)        # 注意负号：实测 +yaw = 顺时针，与右手系相反
   pitch = atan2(z, √(x²+y²))
   ```
3. **激光笔闭环**（可选）：摄像头识别光点 → 自动修正

## 5. 面试可能追问的问题

**Q：为什么不用 SimpleFOC？**
A：想搞清楚底层。SimpleFOC 封装了 PWM、ADC、变换，出问题只能黑盒调参。自己写之后，震动那个问题我能一路追到"loop 频率差了 18 倍"这种层面。

**Q：三环为什么要串级，不能一个 PID 直接控位置？**
A：串级把"位置误差"翻译成"速度需求"，再把"速度误差"翻译成"力矩需求"，每一环只负责一件事。好处是每环都能单独限幅（速度限 30 rad/s 保护机械、电流限 2 A 保护驱动），而且内环带宽高，对外环的扰动抑制更好。

**Q：积分项为什么要限幅？**
A：anti-windup。目标长期达不到时积分会一直累加，等目标反向时要很久才能退回来，表现为"反向反应特别慢"。限幅让积分最多到输出上限就不再涨。

**Q：编码器只有 12 bit，精度够吗？**
A：AS5600 是 4096 线，单圈分辨率 0.088°。做指向够用（激光笔 3 米外 0.088° ≈ 4.6 mm）。不够就上 14 bit 的 AS5047 或用插值。真正的瓶颈不是分辨率，是**多圈累加的可靠性**——跨圈时读数会从 4095 跳回 0，处理不好就会丢圈。

**Q：为什么控制频率这么重要？**
A：离散化后 PID 的积分增量正比于采样周期。频率降低 18 倍，等效积分增益就放大 18 倍，直接把系统推到不稳定。所以参数不能跨平台照抄，必须先对齐采样率。

**Q：CAN 和 CANopen 差在哪？**
A：CAN 只定义物理层和数据链路层（帧格式、仲裁、CRC）。CANopen 是在上面的一层**应用协议**：规定了对象字典、状态机、PDO/SDO、NMT。用自定义 CAN 帧只能自己跟自己通信；上 CANopen 之后，任何支持 CiA 402 的主站（PLC、ROS 的 canopen 驱动）都能直接控制它。

**Q：如果要做到 1 kHz 的力控带宽，瓶颈在哪？**
A：现在 loop 是几千 Hz，理论上够。瓶颈在：① 电流采样只有双低侧电阻，噪声和零漂大；② 没有力矩传感器，只能靠 `Kt×iq` 估算；③ I2C 读编码器是阻塞的，会引入 jitter。要做高带宽力控得换成 SPI 编码器 + 同步采样 ADC。
